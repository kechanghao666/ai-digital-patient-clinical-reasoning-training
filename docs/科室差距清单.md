# 科室与亚专科建制：现状盘点与差距清单

核对日期：2026-11-25（北京时间）。仓库 `E:\AI数字病人临床思维训练`，分支 `codex/feedback-protocol-fix`，基线提交 `43259be`。本轮为离线盘点：**真实模型调用 0 次**，未部署、未上传凭据或本地数据、未新增临床规则、未批量建科室。

本清单回答三个问题：现在系统里到底有什么、按什么分类参照、离“可按院校启用的科室建制”还差什么。覆盖表另见[第一阶段覆盖表](第一阶段覆盖表.md)。

## 一、结论摘要

| 口径 | 数量 | 判定依据 |
| --- | --- | --- |
| 已建科室（系统内可作为建制对象） | **0** | 无科室实体、无层级、无受控字段；`CaseDefinition` 只有自由文本 `specialty` |
| 有病例的专科（按病例标签归并） | **5** | 心内、普外、神经内、呼吸内、内分泌；5 个 `case_id`、5 个公开编号、11 个版本文件 |
| 可完整训练（开发模式） | **5** | 每科取最新版本；问诊→开单→回报→病历→鉴别→诊断→处置→封存→评分链路有工程闭环 |
| 可完整训练（生产模式） | **0（初始）** | 仓库随附 11 个版本全为 `draft`；教师资产目录为空时初始无已发布病例。教师可用页面现有“复制为新草稿”生成副本，经校验→送审→真实医学审核→发布后才对学生可见 |
| 已审核（系统发布状态） | **0** | `reviewer` / `review_date` 全为空 |
| 已审核（医学专业） | **0** | [五专科审核记录](clinical-review-and-evaluation.md)五行均为“待填” |
| 教学依据已审核 | **0 / 9** | `knowledge/teaching_basis/manifest.json` 状态 `draft_unreviewed` |

**一句话结论**：现有资产是“5 个专科标签 + 11 个开发草稿版本”，不是“5 个已建科室”。“复制为新草稿”入口已经存在，复制后仍是草稿；生产初始为 0 指的是“草稿 + 空教师资产目录下没有已发布病例”，不是复制链缺失。科室建制、复制可用、发布可用与医学审核是四件不同的事，本清单分开记账。

## 三、建议的三级模型（仅设计，未落库）

```
L1 科室（department）       例：内科、外科、急诊医学科
  └─ L2 亚专科/专业方向      例：心血管内科专业、普通外科专业
       └─ L3 教学病种/病例    例：STEMI-001（CASE-001），多版本归并为一个病种
```

约束：

1. 一个 `case_id` 只归入一个 L3，多版本不重复计数。
2. L1/L2 使用**受控字典**，不由教师自由输入；参考目录按选定分类覆盖，逐项标明来源；本校启用项和已有病例分别计数。
3. “急诊”在当前五个病例里是**就诊场景**（标签写作“心内科/急诊”），不是第六个科室；可作为平台科室单独建模，但不计病例。
4. 科室字典须能按院校启用/停用，因为参考目录不等于本校开设清单。

### 4.4 为什么“初始生产可见病例 = 0”

代码路径是确定的，不依赖运行观察：

1. 仓库随附的 11 个病例文件 `review_status` 全部是 `draft`。
2. 学生创建训练调用 `resolve_for_student(..., include_unpublished=_development())`；`APP_ENV` 缺省为 `production`，此时只接受 `published`。
3. 内置病例位于 `cases/`，不属于 `_teacher_keys`；`transition()` 对非教师病例直接拒绝，因此内置病例不能**直接**发布。
4. 但页面已有“复制为新草稿”：[`newDraft()`](../web/src/pages/teacher/CaseManager.tsx) 克隆整份病例，生成 `TEACH-*` 的 `case_id`、标题加“（新草稿）”、版本 1、状态 `draft`，删除公开号；保存走 `PUT /api/teacher/cases/{case_id}`，由 `save_draft()` 分配新 `public_id`（`CASE-T1xx`），`authored_by` 记为当前教师。原内置文件只读。
5. 副本随后走 `draft → validated → under_review → published`；发布需要真实医学审核人、日期和确认。仓库与空教师资产目录中当前没有已发布病例。

结论：初始为 0 的原因是“随附版本全是草稿 + 教师资产目录为空 + 尚无人完成医学审核并发布”，**不是复制入口缺失**。复制→保存→校验→送审这段可以走通；能否进入生产教学取决于医学审核与发布，而不是另建克隆功能。

## 五、主要缺口

### 5.1 病例维护

| 缺口 | 现状 | 影响 |
| --- | --- | --- |
| 副本不记录来源 / 无批量复制 | 页面“复制为新草稿”生成新的 `TEACH-*` 编号，不保留源 `case_id@version`；一次只能复制一份 | 无法追溯副本来自哪个内置版本；院校批量建课时效率低 |
| 副本不继承教学依据 | 依据条目按 `applies_to_cases`（如 `STEMI-001`）绑定；副本使用新 `case_id`，保存与送审返回“缺少适用于当前病例的专科临床依据”警告 | 副本可训练、可封存，但反馈依据需教师重新映射或补充；警告不等于已审核 |
| 停止后不可恢复/归档 | 已实现按版本“停止新训练”（集成库记录，重启生效）；`PUBLISHED` 仍无出边，停止不可撤销，也不能归档 | 误停只能另发新版本；旧病例保留但不再接收新训练 |
| 无科室/亚专科字段 | 仅自由文本 `specialty` | 无法按科室统计、授权、筛选 |
| 无版本对比/回滚 | 版本按文件递增保存，无 diff/回滚入口 | 教师改错后难以定位差异 |
| 无批量导入/导出 | 仅单病例编辑 | 院校接入成本高 |
| 审核人不可核验 | `reviewer` 为自由文本，无账号绑定 | “已审核”只能是文字声明 |

### 5.2 教学管理

有班级、成员、任务和完成进度；缺学期/课程/课表、分组与轮转、带教老师分配、成绩册与导出、补考/重做策略、按科室的教学计划。管理员角色不存在，只有 `student` / `teacher` 两种角色（`accounts` 表有 CHECK 约束）。

### 5.3 权限审计

已有：教师只能操作自己的班级（`owned_class`）、评分/反馈复核记录带 `teacher_id` 与时间、登录失败有 `login_attempts` 限流表、停用账号会清除会话。

缺口：账号创建/重置/停用无独立审计表；病例发布端点丢弃了当前教师身份（`publish(..., _: str = Depends(current_teacher))`），发布记录里没有操作者 ID；无管理员/教研主任角色；无导出与查看敏感数据的审计。

### 5.4 异常恢复

已有：请求幂等、`state_version` 并发校验、回合凭证过期与取消、迟到响应丢弃、封存后拒写。

缺口：无备份/恢复演练脚本与记录；无监控告警；无数据修复工具；SQLite 单写者与多进程限制未在部署文档中给出明确边界；已发布病例文件损坏时无回滚流程。

### 5.5 独立部署

已有：`requirements.lock`、GitHub Actions（测试/样本/编译/依赖审计）、[部署指南](deployment.md)、环境变量示例。

缺口：无容器镜像/编排；无配置启动自检清单；无独立机器从零复建记录；无升级/迁移手册；无反向代理、HTTPS、进程守护说明；生产数据初始化（首个教师、首个可发布病例）没有步骤。

## 六、现有复制流程与两个独立后续任务

### 6.1 现有流程（本轮验证，不新增入口）

教师病例管理页已提供“复制为新草稿”（[CaseManager.tsx](../web/src/pages/teacher/CaseManager.tsx) 的 `newDraft`）：

1. 教师打开内置病例（如 `STEMI-001` v3）。
2. 点“复制为新草稿”：前端克隆整份病例，生成新的 `TEACH-*` `case_id`，标题追加“（新草稿）”，`version=1`、`review_status=draft`，删除 `public_id`。
3. 保存：`PUT /api/teacher/cases/{case_id}`，服务端 `save_draft()` 分配新的 `CASE-T1xx` `public_id`，`authored_by` 记为当前教师，原内置文件只读。
4. 依次“标记结构校验通过”→“提交医学审核”。
5. 只有真实医学审核完成后，才可在 `under_review` 状态填写审核人、日期并勾选确认发布。

边界：复制不记录来源 `case_id@version`；内置病例不能直接送审；发布后审核状态不可变更，但可按版本“停止新训练”（见[病例停止新训练](病例停止新训练.md)），停止不可恢复；无人完成真实医学审核时必须停在送审，不得在页面虚假勾选。

本轮隔离实测（2026-11-25）：临时数据目录、`APP_ENV=production`、本地认证合成师生、`NEXENT_MODE=simulator`。学生初始 `GET /api/cases` 为 200 且空；教师页面打开 `CASE-001` v3，复制为 `TEACH-4e026058`，保存为 `CASE-T100` v1 草稿；源文件 SHA256 前后一致；校验→送审后状态 `under_review`，学生仍为 200 且空；草稿直接发布返回 409；审核复选框未勾选、发布按钮禁用，未发布。发布后的可见性与训练行为只在[隔离自动化测试](../tests/test_case_copy_publish_visibility.py)中用明确标注的模拟审核数据验证，不代表真实医学审核或生产发布。证据为本机临时目录，不随仓库分发。

| 类别 | 项目 |
| --- | --- |
| 已验证（页面/接口/文件） | 现有复制入口；保存分配新 `public_id`；草稿与待审核状态学生不可见（HTTP 200 空列表）；草稿跳级发布 409；校验→送审；源文件哈希不变 |
| 仅测试夹具验证（非真实发布） | 发布后学生只见该版本、可创建训练并封存、后续教师草稿不改变已发布版本与历史训练版本（审核人明确写为“模拟审核（测试夹具，非真实医学审核）”） |
| 尚未测到 / 未取得 | 真实医学审核、真实学生使用、真实发布后的生产运行、依据适用性重新核对后的反馈链 |
| 确实缺少 | 副本来源记录、副本依据的显式关联与核对、停止后的恢复/归档、版本回滚、批量复制、发布操作者审计、科室/亚专科字段 |

| --- | --- | --- |
| 副本来源 | 复制后丢失源 `case_id@version` | 复制/保存时记录来源，可追溯 |
| 依据继承 | 副本使用新 `case_id`，原病例依据不适用 | 复制时显式映射/迁移依据，或要求教师为副本重新选定并审核 |
| 发布审计 | `publish` 端点丢弃当前教师身份 | 发布记录含操作者 ID、时间、科室 |
| 停止/恢复 | 已实现按版本停止新训练（重启生效）；不可恢复、不可归档 | 增加恢复/归档；停止与恢复均留审计 |
| 版本治理 | 文件按版本递增，无 diff/回滚 | 至少可定位差异并回滚到上一版本 |

验收：复制一条内置病例，记录副本来源；发布后用模拟审核数据验证学生只见已发布版本；将副本下线，学生不能再新建训练，历史训练仍可打开且指向原版本；发布记录可查到操作者。全程离线，真实模型 0 次。

### 6.3 后续任务 B：受控科室/亚专科建制

目标不是把现有 5 个标签固化成系统上限，而是形成**可按院校启用的完整目录**：

1. L1 科室 / L2 亚专科使用受控字典，收录范围按核实的分类版本确定，另设院校启停；首批将五个已有病例映射到适用项，急诊就诊场景单列。
2. `CaseDefinition` 增加 `department` / `subspecialty`（或等价受控编码），保存与发布时校验取值在字典内；保留 `specialty` 文本用于展示兼容。
3. 学生病例库按 L1 + L2 两级筛选；未建病例的科室不出现在下拉中。
4. 发布门禁要求科室/亚专科必填且在字典内，保留现有医学审核确认与来源校验。

验收：字典内新增一个院校启用/停用项，学生筛选随之变化；空科室不显示；缺科室或字典外取值明确报错且不落库；不批量建空科室，不编写未经审核的临床规则。

### 6.4 为什么不是其他选项

- **新增克隆接口**：复制入口已经存在，再加一个接口不解决来源、下线与审核问题。
- **先批量建科室目录**：会产生大量 0 病例的空科室，违反本轮约束，也不能让生产环境多出一个可训练病例。
- **先补四科临床依据/规则**：属于未经审核的临床内容，不解决发布与治理缺口。
- **先做学生端界面改版**：属第三阶段，本轮明确不混做。
