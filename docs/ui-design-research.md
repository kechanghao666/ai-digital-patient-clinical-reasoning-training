# 教学工作台界面研究与设计决定

2026-11-13。在工程修复和官方要求逐项核对后开展。目标是让学生准确知道正在训练哪个病例、哪些内容已保存、如何查看证据，让教师能核对原始记录。沿用Streamlit 1.67及现有后端，不加入新的框架、生产依赖或额外医学推断。

## 官方资料及采用方法

本轮实际读取以下六个官方页面，均HTTP 200；正文哈希见[来源记录](evidence/2026-11-13-ui-sources.json)。网页会更新，规范版本和本项目的实际实现需分别核对。

## 信息结构与可视化

病例库保持“选择病例”和“恢复训练”两个明确入口。按专科筛选只作用于新病例列表，已保存训练不受影响；预览用主诉和版本帮助确认，不额外披露隐藏诊断或事实。筛选不生成训练，只有明确点击开始才创建记录。

训练页的病例摘要在四页签上方，模拟时间、记录数和封存状态持续可见；病情变化仍醒目显示。未提交的病历/鉴别/诊断继续阻止意外封存或返回。断线仍显示缓存只读提示，失败不伪装成功。

回放采用按原始顺序排列的可展开事件，标题包含原事件编号、操作和模拟时间。按操作类型筛选时不重新编号；显示“筛选数/总数”，不把筛选隐藏误解为缺失数据。展开保留原患者回答、检查、判断、处置与病情变化。空记录有下一步提示，查看和筛选不写入业务数据。

评分沿用分项进度条和原始数值表；总分、教师裁定、反馈批准状态分开，不增加“通过/不合格”判定、雷达图或无依据的能力排名。没有真实统计数据时，不绘制趋势、平均分或学生比较。

## 视觉规则

- 背景`#F5F7FB`，内容区白色；正文`#172B46`、次要文字`#53657D`、操作/焦点`#076B70`。共享语义变量管理现有CSS，病例摘要左侧强调线帮助辨认区域。
- 文字、图标、边框共同表达状态；分数和状态不只依赖红绿颜色。正文可换行，不使用固定高度裁剪主诉或回放。
- 复用原生控件、控件标签、44px主要触控高度与焦点轮廓；减少动画偏好沿用。表格保留数据查看能力，窄屏主体不应横向溢出。
- 桌面保留问诊/检查双栏，窄屏纵向排列；320px页签分两行，避免挤压四个完整中文标签。长列表通过筛选和逐项展开减少滚动负担。

## 验证与边界

自动检查覆盖专科筛选对应病例、回放过滤/顺序/只读、既有未提交保护、身份隔离和教师草稿限制。浏览器使用真实Edge和合成训练，覆盖实际控件、页面截图及窄屏几何，结果汇总到[界面说明](ui-workspace.md)。来源研究只是设计依据，不能替代视觉检查或真人测试。

仍需真实学生/教师的任务完成观察，以及屏幕阅读器、全部错误分支、所有浏览器/缩放组合的完整无障碍评估。当前主要性能瓶颈是真实模型请求时延，界面改版不能将其宣称已解决。
