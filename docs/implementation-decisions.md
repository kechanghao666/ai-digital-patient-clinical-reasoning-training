# 实施决定记录

## 当前状态

- 工程阶段：第一例 STEMI 本地确定性闭环实现中。
- 病例状态：自造工程夹具，`review_status=draft`；未伪造医学审核。
- Nexent 状态：提供真实适配器接口和本地模拟适配器；真实平台联调待目标环境凭据/版本。
- 评分状态：规则评分可复算；官方 85% 统计口径、专家/学生证据待外部确认。

## 已落地决定

1. 后端持有 owner/session/case/version，学生不能指定平台会话或任意工具参数。
2. 事实按原子 fact_id 授权；问到性质不自动放行放射等其他事实。
3. 检查结果按订单实例和模拟时间推进，缺失/待返回/失败不显示为正常。
4. 治疗只有结构化确认执行才产生执行事件；计划和未确认文本不推进状态。
5. 评分从冻结事件读取，病历补写不创建早期事件。
6. 学生公开编号使用 CASE-001，避免把 STEMI 诊断泄露在公开标识中。
7. 学生 HTTP 响应不直接序列化内部 SessionState/Event；公开投影移除 owner、内部病例编号、请求哈希、原子事实编号和调试状态。
8. SQLite 写入使用 state_version 条件更新；旧快照竞争返回 409，不允许静默覆盖另一条事件。
9. 封存动作使用统一幂等入口，并在封存时绑定评分快照；合法旧请求重试只返回原结果。
10. 适配器回答必须在学生响应出口通过授权事实门禁；不通过时只返回安全模板，且仅登记最终实际披露的事实。
11. 诊断评分仅接受有边界的肯定表述；否定不命中，不确定表述和无法可靠关联的鉴别证据返回 `needs_review`，不自动给满分。鉴别检查证据必须来自已经返回的检查事件，开单事件不等于已获得结果。
12. 延误规则触发的事实只有在同一 WAIT 事件中写入 `fact_ids_revealed`、公开变化文本和会话 `clinical_updates` 后，才视为已向学生披露；前端必须展示该变化，不能仅凭内部 `clinical_state` 推断学生已知。
13. Streamlit 对临时网络/5xx 错误保留最近一次会话快照；只有 401/404 才清除训练入口。动作失败不触发刷新，错误保存在下一次渲染中，避免操作未执行却丢失提示。
14. 诊断自由文本只对每个目标诊断断言分类：自动给分仅限明确、有限且完整匹配的肯定表达白名单；明确否定也必须完整匹配目标诊断的否定白名单。否定词若修饰其他疾病，或文本包含无法唯一判定的复合、未证实、历史和冲突表达，统一进入 `needs_review`，不按整句查词直接完成零分；无关疾病（例如 NSTEMI）不能覆盖目标 STEMI 的明确肯定。
15. 前端错误按 `session_read`、`ask`、`action`、`diagnosis`、`differential`、`treatment`、`seal`、`score` 等请求范围管理；成功响应先清除同范围错误再返回，读取恢复不会清掉未重试的动作错误。错误不在请求开始前直接绘制，而是在本轮所有请求完成后通过可清空占位区域按最终状态渲染，保证恢复成功当轮移除旧提示。封存评分区域必须显式显示整体复核状态。
16. 前端所有可改变训练轨迹的请求都保存“操作范围、规范化 payload、request_id”；网络/应答不确定时用相同 payload 和 request_id 重放，成功后才清除待决操作。payload 改变或明确开始新操作时才生成新的 request_id，避免丢失应答后的治疗重复执行或等待重复推进。
17. “优先开立”类检查评分必须由病例 rubric 显式配置顺序约束；本地 STEMI 夹具使用 `first_exam_before_wait`，要求该检查是首个检查操作且此前没有正向等待。没有显式顺序配置的检查仍只按是否开立评分，不从描述文字推导医学时间阈值。
18. 学生端必须把鉴别诊断、病历记录、训练回放、已有训练恢复和封存后新建训练接入同一会话闭环；病历记录使用 `update_notes` 事件持久化，回放只展示公开事件投影，不暴露内部病例、事实或检查标识。
