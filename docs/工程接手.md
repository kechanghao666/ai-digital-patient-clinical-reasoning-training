## 当前唯一编码任务

- `backend/app/main.py` 的问诊成功路径先保存训练状态，再返回学生可见的 `event`；请求重放也返回既有事件。`web/src/pages/Training.tsx` 当前在 POST 成功后调用 `reload()`，依赖刷新后的列表显示回答。不要改后端可信提交协议，也不要渲染未经校验的文本。
- 本机替身在同一 CASE-001 训练的不同问句上做了对照：只延迟 GET 的两轮中，POST 响应标记在 114.4 / 129.6 ms，但新增回答进入 DOM 在 2135.6 / 2145.6 ms。该探针标记的是 fetch 返回和 DOM 插入，不是响应体读取完毕、浏览器绘制或供应商首 token；不能据此断言真实模型达到了 5 秒或推断真实瓶颈。本机证据：`local-only/ask-latency-1d630d1-20261124/`，按设计不随仓库分发。
- 先复现：挂起同一训练的刷新 GET；POST 成功时，用真实浏览器确认新增回答现在仍未显示。再最小修改，使 GET 放行前即可看到 POST 返回的已保存问答。按训练和事件标识去重，不提前改变评分或其他临床状态。
- 验收：刷新成功后不重复；刷新失败不抹掉已保存回答，只提示重新读取，不让学生重发；POST 失败时保留输入且无新增；同请求重放不重复展示、不重复写入；切换训练后不串答。保留能防止回退的行为测试，执行相关离线测试、前端类型检查和构建；若修改前端，将对应构建产物纳入变更。报告事件先后，不靠绝对毫秒断言刷绿。
- 本轮真实模型调用上限 **0**。使用独立本地实例、合成病例和替身。原始证据、训练库、凭据不读作交接素材，不上传；不切换默认 `dual`，不部署、不启动第三阶段。最近一次全量基线是 683 项通过，不是未来修改后的结果。
