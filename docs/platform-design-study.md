# 主流AI平台与生产力软件界面研究

调研与实现日期：2026-11-13。目标是重构可运行的医学教学工作台，包括学生病例选择、训练、复盘与教师工作空间。使用官方产品说明、设计团队复盘及规范作为依据；未声称登录体验所有付费产品或掌握它们每个灰度版本。旧产品发布说明用于研究交互模式，不作为当前完整界面快照。

## 研究方法

先按任务拆解界面：进入工作空间 → 找到对象 → 对话/操作 → 查看结果 → 保存与恢复 → 审核。对每个参照检查导航、上下文、主次动作、信息密度、错误/空状态、AI透明度及窄屏变化；再区分可直接采用、需要改变语义、不适合医学教学的设计。只有接入真实状态、可点击且有验证的内容进入产品。

本轮通过联网检索与官方页面核对十二个产品/规范体系。直接抓取记录包含成功正文哈希及失败记录，见[来源记录](evidence/2026-11-13-platform-design-sources.json)。OpenAI部分页面直接HTTP访问返回403，Notion/Perplexity等直接请求曾超时；其相应官方内容另通过网页检索工具读取。Material网页旧地址404/JS空壳没有当作有效证据，改用Android官方自适应布局文档；Apple空壳页改读官方DocC内容。没有用HTTP 200自动判定已经读取有效正文。

## 由研究得到的设计系统

### 信息结构

侧栏只承担角色和目的地：学生进入病例库/我的训练；教师进入病例编写、反馈复核或评分裁定。身份与服务地址放在连接设置内。进入训练后，侧栏只保留返回、当前病例和状态，避免绕过未保存保护切走。

病例库从单一下拉框改为搜索与专科筛选的双列卡片，每张卡片有专科、编号、版本、主诉、审核状态和明确开始按钮。没有搜索结果时显示恢复方法，不创建任何会话；搜索只覆盖已经公开的字段。首页最近训练是实际已有记录，“我的训练”通过真实ID恢复，不以列表位置猜测身份。

训练页压缩为病例标题、公开上下文条、模拟时间/操作数/状态与四页签。问诊左侧是可持续阅读的对话和输入，右侧检查开单、时钟和回报；病历与判断并排；处置执行和封存分别成区。将输入移入原生表单支持Enter提交，仍使用原幂等请求流程。检查结果采用中性展示，避免将“已经回报”涂绿误导为“结果正常”。

复盘先呈现原分总览和五环节条形摘要，再展开逐项说明；教师裁定另列，模型反馈待复核状态明确。回放保留原事件号和真实顺序。不会以绿色、封存或模型调用成功表示正式医学合格。

### 视觉与交互

- 色彩：近白工作区、浅灰绿侧栏、深灰正文、低饱和绿色操作；警示使用琥珀色并保留文字。共享CSS语义变量和Streamlit主题同步。
- 层级：页面标题回答“当前在哪里”，病例栏回答“正在处理谁/哪个版本”，面板标题回答“这里做什么”。使用系统中文字体，不依赖外网字体下载。
- 动作：卡片开始、问诊提交、病例保存和封存均为真实操作；禁用状态由现有业务条件决定。仍要求明确确认处置，未提交内容继续阻止封存/返回。
- 响应：桌面双栏，窄屏纵排；320px导航可换行。控件保留可见标签和键盘焦点，减少动画偏好继续生效。没有将缩小字号作为主要适配手段。
- 状态：数据/内容/颜色同时核对；不会伪造课程完成率、学生排名、临床审核人或“在线专家”。没有加入无法操作的装饰按钮。

## 工程范围、验证和取舍

变更集中在frontend/app.py、teacher.py、styles.css及主题配置；保留API、MCP、病例、评分及复核协议。复用原生控件和现有请求/错误处理，不引入新框架或依赖。新增搜索空状态和恢复指定历史训练的自动检查，更新教师自建病例卡片选择回归；原有授权、草稿保护、封存只读与教师复核边界继续验证。

实际截图发现固定工具栏遮挡顶部提示，已增加桌面间距；等待输入和页面重绘后再截图，避免把中间状态当成最终布局。开发预览重启/另启曾被本地自动审批阻止，后续复用既有8506预览完成验证；没有绕过保护或停止其他应用。前端支持FRONTEND_API_URL预设连接，缺省仍为8000；当前预览实际通过页面设置连接8005。

最终自动检查、浏览器完整流程、真实时延与截图见[重构验证](evidence/2026-11-13-design-rebuild.json)和[界面说明](ui-workspace.md)。没有进行真人可用性访谈、付费平台全功能实测或完整读屏审核；不把界面改版当作临床资产、身份系统、模型语义及响应性能门槛的关闭证据。
