## 一、范围与方法

| 口径 | 数量 |
| --- | --- |
| 病例版本文件 | 11 |
| 独立病例（`case_id`） | 5 |
| 按版本计的事实 | 144 |
| 拆成多个片段的事实 | 121 |
| 片段总数 | 323 |

方法：用生产代码的 `fact_fragments()` 重新拆分每个事实，按四类结构做启发式标记，再对命中项做 API 复现或人工阅读：

1. **否定**：父事实为否定极性，但某个片段不含否定词。
2. **主体**：父事实含家属主体，但片段既无家属词也无主体前缀。
3. **时间范围**：父事实含时间，但只有部分片段带时间。
4. **并列/话题**：片段内仍含“、/和/及/或”，或片段的临床意图集合互不相交。

启发式共标记 80 条按版本计的事实（同一事实可命中多类），逐版本索引见附录。**启发式命中不等于缺陷**；下表只列已复现、已修复和需人工判断的代表项。完整启发式列表保存在本机 `local-only/fragment_audit_20261126.json`，不随仓库分发。

计数快照已固化为可复现测试：[test_fact_fragment_audit.py](../tests/test_fact_fragment_audit.py)。

## 二、已复现并已修复

### 2.1 过敏史后含糊追问带出手术史

| 项目 | 内容 |
| --- | --- |
| 病例/版本 | `STEMI-001` v3；`DKA-001` v2 |
| 事实 ID | `f_allergy`（两例同结构） |
| 原文 | 没有药物过敏，也没做过手术。 |
| 片段 | `f_allergy#a1` 没有药物过敏；`f_allergy#a2` 没做过手术 |
| 修前 | “有药物过敏吗？”→“没有药物过敏。”；“后来呢？”→“没做过手术。”，`f_allergy` 进入 `disclosed_fact_ids` |
| 修后 | “后来呢？”→“暂时就这些了。”，`f_allergy` 保持未完整披露；“以前做过手术吗？”→“没做过手术。”，此时才完整披露 |
| 修复位置 | [disclosure.py](../backend/app/disclosure.py) `_last_topic_question` / `_unanswered_atoms_match_topic` / `_continue_turn` |
| 规则 | 含糊追问继承最近一次**非追问**问句的临床意图；只有该事实剩余片段**全部**回答同一意图时才继续，否则收束。未按病例编号或问句原文特判。 |
| 回归 | [test_continuity.py](../tests/test_continuity.py) 参数化覆盖 `CASE-001` 与 `CASE-005` |

修前证据：`local-only/o3-allergy-prefix-20261126/result_before.json`（本机）；修后证据：`local-only/o3-allergy-prefix-20261126/result_after.json`（本机）。

### 2.2 评分影响

- `CASE-001` v3 的 `f_allergy` **不是**任何量表项；修前“完整披露”只改变 `disclosed_fact_ids` 与 `disclosed_fact_count`，不改当前规则分（修前/修后封存总分均为 0，且该训练未操作其他评分项）。
- 同一机制适用于其它多片段事实：父事实只有在全部片段都实际回答后才计入 `matched_fact_ids`，而 `scoring.py` 的 `ask_event` 证据只读取 `matched_fact_ids`。因此本次修复保护的是“含糊追问不应完成父事实”这一通用计分前提。
- 当前 11 个版本中，被启发式标记且同时是量表项的复合事实共 **22 条**（见第四节）；本轮未复现它们因含糊追问而被误计分的例子，列为人工抽查项。

| 例子 | 复现 | 现状 | 为什么待判断 |

| `STEMI-001` v3 `f_ros`：没有发烧、咳嗽，也没有头晕、心慌，大小便都正常。 | 问“有没有发烧？”答“没有发烧、咳嗽。” | 片段 `f_ros#a1` 同时含发烧与咳嗽 | 问一个症状会顺带回答同组另一个；若拆分，必须把共享否定“没有”同时复制到两个片段，否则会把“没有咳嗽”误拆成“咳嗽” |
