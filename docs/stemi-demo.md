# STEMI 中期演示与独立复现

## 目标环境

1. 按[项目运行说明](../README.md#本地运行)安装锁定依赖，使用独立的 API、MCP 和训练数据库。确认后端与 MCP 使用同一数据库及知识目录。
2. 在目标 Nexent v2.8.4 实例创建模型及嵌入配置。验证模型能实际返回内容，并按[配置字段清单](agent-config-draft.md)检查上下文与输出预算。
3. 注册鉴权 MCP，扫描可信 MCP 工具后，以[实际角色配置](agent-config-draft.md)中的角色白名单分配工具。选择compact时，反馈只启用submit_feedback并使用[分轮提示](compact-feedback-prompt.txt)，教学依据由后端绑定；不要照搬历史review_tool配置中的平台知识库搜索工具。选择review_tool时另按其配置上传草稿依据并验证检索。服务密钥和回合凭证从目标环境的受保护配置加载。
4. 导入两个平台导出的配置。核对目标模型、工具与反馈知识库的映射，开启 allow_chat_metadata，确认病人不挂反馈库，发布并记录两个版本。向项目后端配置目标北向地址和两个内部名称。
5. 用一条全新模拟训练执行下表，再用第二个演示账号核对隔离。记录所用版本、各步状态、工具调用及可见回答时间。正式提交前还需在独立实例复跑。

## 建议演示顺序

| 操作 | 观察和取证 |
| --- | --- |
| 学生打开 CASE-001，发起问诊 | 显示教学说明。计时从点击提交到首个可见的有效患者回答。后台应有读取和事实选择工具记录。 |
| 开单、推进模拟时间、查阅结果 | 页面区分待回报与已回报。回放保留开单和回报顺序。 |
| 保存病历，提交鉴别和诊断，确认模拟处置 | 分别记录提交与执行，展示所用证据。 |
| 封存并查看五环节评分 | 封存后输入禁用，记录封存快照。 |
| 生成反馈，再刷新与重试 | 记录反馈时间、五环节、依据、回放。失败时保留原分，恢复后用原请求重试。 |
| 教师切换工作区并载入封存训练 | 展示病例管理、事件证据和反馈复核入口。 |

按一次完整演示准备录制素材。若反馈尚不稳定，实际展示故障与恢复行为，标注已验证范围。正式验收按[验收计划](acceptance-plan.md)补齐异机部署、随机用例及正式人员评测。
