# 项目全面复盘（2026-11-13）

本轮起因是用户在独立账号预览中实测“效果很差”：常见问法得不到回答。复盘结论是，问题不在界面，而在两处底层：问诊理解只做触发词子串匹配，五个病例本身只有7–10条事实。本轮先修这两处，再对账号与评分做独立审查并修复确认的缺陷。所有病例仍为未经医学审核的自造草稿。

## 一、问诊质量：根因与量化

用一组40个本科生常用的口语问法（开场、现病史、伴随症状、既往/个人/家族史、寒暄与索要诊断）逐科测量，修复前每科只有8–17问能得到病例内容，其余全部返回“我不太确定您的问题”。同时发现误匹配：

| 问题 | 修复前 | 原因 |
|---|---|---|
| 腹痛、DKA病例问“有高血压糖尿病吗” | 返回小便情况 | 触发词“尿”是“糖尿病”的子串 |
| 腹痛病例问“有没有咳嗽” | 返回“走路或咳嗽时更明显” | 触发词粒度过粗 |
| 多条事实同时回答 | “……过敏。，自己量过……” | 以“，”拼接整句 |
| 胸痛病例问哪里疼、有没有出汗、家族史等 | 无法回答 | 病例里根本没有这些事实 |

## 二、本轮改动

问诊层（`backend/app/disclosure.py`）改为两步：先用37类病史意图识别口语问法，再路由到病例已有的触发词；意图只做路由，不生成任何临床内容。误匹配用屏蔽词处理（如“糖尿病”“尿常规”中的“尿”）；询问某一具体疾病时，只有病例没有直接命名该病的事实才回落到一般既往史，避免问糖尿病却披露房颤。没有可披露事实的回合分三类给固定回答：寒暄（“医生您好。”）、索要诊断或结果（“这个我也不清楚，得请医生帮我看看。”）、识别为病史条目但本病例未配置（“这个我没太注意，说不好。”）。这些回答不含任何病例事实，仍经过原有泄露检查，事件中另记 `turn_kind` 供教师判断病例缺口。

病例层新增五个草稿版本：STEMI v3，阑尾炎、卒中、肺炎、DKA 各 v2。补充一般情况、疼痛部位、伴随症状、个人史、家族史、过敏/手术史、既往发作、就诊经过和系统回顾阴性。原有事实文字、检查、评分量表、规则全部保持不变，旧版本文件未改，已开始的训练继续使用原版本。STEMI 知识依据的版本映射同步加入 v3。新增事实中有几条带教学含义，审核时应重点看：STEMI 的“后背没有撕裂样疼”（主动脉夹层鉴别）和“父亲有冠心病”，卒中的“没有糖尿病”和“哥哥中过风”，DKA 的家测血糖“HI”和月经/妊娠情况。

| 病例 | 版本 | 事实数 | 40问中披露事实（前→后） | 仍未配置 |
|---|---|---|---|---|
| CASE-001 胸痛 | v2→v3 | 9→21 | 10→34 | 1 |
| CASE-002 腹痛 | v1→v2 | 10→18 | 17→33 | 2 |
| CASE-003 卒中 | v1→v2 | 8→19 | 11→31 | 4 |
| CASE-004 肺炎 | v1→v2 | 8→17 | 8→31 | 4 |
| CASE-005 DKA | v1→v2 | 7→18 | 10→32 | 3 |

上表的40问参与了调参，存在过拟合。为此另写了一组30问、调参前首测：五科合计150次中，披露事实61%，可理解（含寒暄与“未配置”）87%，13%无法理解。其中4个问法（“哪里不得劲”“饭吃得下吗”“长期吃的药”“贵庚”）随后已补，因此这组数字也不能再当作独立结果。真实学生问法的覆盖率仍需用实际训练日志统计。

## 三、独立审查发现与处理

另起一个审查代理只读审查账号与评分代码，并用可运行用例复现，确认以下问题，均已修复并加回归测试（`tests/test_review_fixes.py`）。

| 级别 | 问题 | 处理 |
|---|---|---|
| 中 | 前端由 Streamlit 服务器代为登录，所有用户来源都是 127.0.0.1，共用每分钟120次的来源限流；任何人连续试错即可让全站无法登录 | 回环来源只按账号限流；外部来源仍保留来源限流 |
| 中 | 学生在一个证据框里写“A、B”两条已引用事实，整条被判“无法对应”，鉴别分减半并转复核 | 整段无法对应时按“、；，”拆分，只有每一段都能对应已引用事件才按条计分；含无法对应片段的仍整体转复核 |
| 低 | 超长密码触发的422错误把明文密码写回响应体 | 改为处理函数内校验长度，错误信息不含输入 |

审查确认无问题的部分：PBKDF2 60万次加盐哈希与等时比较、令牌只存哈希且可撤销、教师接口角色校验、会话按 owner 隔离、开发身份头只在 development+demo 下生效、全部参数化 SQL、封存后不可改、问诊只计实际匹配事实、检查只计已回报结果。仍保留的已知限制：账号5分钟内输错5次即锁定，知道账号名的人可反复锁定他人；证据子串匹配偏宽松（4字以上原文片段即可）；一次等待只触发一条延迟规则（当前每例只有一条，暂不触发）。

## 四、其他发现

项目根目录 `KEY.txt` 存有讯飞模型平台的明文 API Key，`local-only/account-preview-20261113/账号信息.txt` 存有预览账号明文密码。两者均被 `.gitignore` 排除、从未进入提交历史，但仍建议把密钥移到项目目录外或系统凭据管理器，并在交付或打包前确认不被带出。

截至本轮，账号系统、界面重构和本轮全部改动都还未提交到 git（`accounts.py`、新病例、新测试等仍是未跟踪文件）。建议尽快在本机提交一次，避免丢失。另外，本轮在只读挂载环境里执行 `git status` 时留下过一个空的 `.git/index.lock`，已删除。

## 五、验证

在 Python 3.10 沙箱中（项目目标为 3.11，用测试专用垫片补 `asyncio.timeout_at`，垫片不进入项目）：全量 549 项通过（原 522 项 + 新增 27 项），`compileall` 通过，十二组工程样本 12/12。项目 `.venv` 是 Windows 环境，沙箱无法直接使用，请在本机用 `.venv` 再跑一次全量测试。

正在运行的 8006/8508 预览仍是旧代码。在项目根目录执行下面的命令重启，账号与训练数据目录保持不变，重启后新建训练才会用到新版病例：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restart_account_preview.ps1
```
