# 智能体任务：“魔擎开发者激励1期-基于Nexent的智能体开发”

> 为加速数据存储与 ModelEngine 智能体生态建设，本次活动面向具备智能体编排与大模型应用实战经验的开发者，围绕医疗健康、政务民生、金融风控、教育科研四大方向共 **32 个技术课题**进行自主设计开发，共同沉淀可复用、可迁移的智能体应用范式。
> 各课题的问题描述、建议功能、交付要求与验收标准详见[《需求包详情与交付要求》](https://atomgit.com/ModelEngine/AgentsHub/blob/main/%E9%9C%80%E6%B1%82%E5%8C%85%E8%AF%A6%E6%83%85%E4%B8%8E%E4%BA%A4%E4%BB%98%E8%A6%81%E6%B1%82.md)。

> 名额为**激励发放上限**，不是报名的可用名额；名额按档次统筹，可在该档次的不同课题间使用。

> **赛制口径**
>
> 1. **公开报名，不限人数**：全部课题开放报名，同一课题可多人同时报名、并行开发；报名先后不决定评审结果，也不设"席位占位"，不存在"名额被抢走"。
> 2. **审核通过才发激励**：表中"名额"为**激励名额上限**（初级 13、中级 15、高级 4），报名不占用名额；只有同时通过基础验收与综合评审的成果才发放激励，未通过者不发放。
> 3. **同题择优**：同一课题多名开发者达标时，按综合评审得分排序、在名额上限内确定获奖名单；达标但未进入名额者发放优秀贡献证书并在社区展示。
> 4. 每一档次激励金仅发放 **1 轮**，每名开发者每档最多获得 **1 次**；同一课题的激励金只发放 **1 份**，不重复计发。
> 5. 激励金为税前金额，个人所得税由发放方依法代扣代缴。

## 🚀 参与流程

> 【第 1 步】[选择课题](#step1) → 【第 2 步】[公开报名（不限人数）](#step2) → 【第 3 步】[报名资格核验](#step3) → 【第 4 步】[课题开发](#step4) → 【第 5 步】[成果验收与评审](#step5) → 【第 6 步】[激励发放](#step6)

### <a id="step1" name="step1" style="position:relative;top:-120px"></a><span style="color:rgb(222, 60, 54)">【第 1 步】选择课题</span>

1. 本次活动面向具备智能体开发、大模型应用或相关领域（医疗、政务、金融、教育）技术能力，并能在活动周期内持续投入的**个人开发者**。
2. 报名前请务必阅读《需求包详情与交付要求》，确认课题的建议功能、交付要求与验收标准。
3. 每位开发者结合个人技术方向，**同期最多可报名 2 个课题**；同一课题允许多人同时报名，不设先到先得、不设席位占位。
4. 难度与档次严格对应：高难度 → 高级任务激励金（￥7,000），中难度 → 中级任务激励金（￥6,000），低难度 → 初级任务激励金（￥5,000）。不得跨档报名或申请跨档计发。
5. **报名不等于获奖**：报名只是进入开发与评审的入口，能否获得激励取决于验收与评审结果；未获激励不影响继续参与后续批次。

### <a id="step2" name="step2" style="position:relative;top:-120px"></a><span style="color:rgb(222, 60, 54)">【第 2 步】公开报名（不限人数）</span>

#### 报名要求：

1. **报名时间**：自本公告公示之日起至该档次激励名额发放完毕或活动截止日为止。期间持续开放报名，**不因他人报名而关闭**。
2. 全部课题均为"开放报名"状态，开发者在本活动帖下方评论区按格式提交报名信息即可；**同一课题允许多人同时报名、并行开发**，互不影响。
3. <span style="color:rgb(69, 176, 118)">报名、代码交付、验收及激励发放的 AtomGit 账号须保持一致并已完成实名认证，否则无法发放激励。</span>
4. 开发者须**一次性提交完整报名信息**，报名信息反馈格式如下：

```
【评论分类】：课题报名
【AtomGit 账号】：
【个人简介】：
【报名课题】：（课题序号 + 名称）
【相关项目或开源经历】：（提供开源链接或作品说明）
【初步技术思路】：（架构思路、智能体分工、知识库与工具规划）
【可投入时间】：（每周可投入时长 + 计划完成日期）
```

> ⚠️ 报名材料须真实完整；存在信息缺失、账号异常或材料虚假的，视为无效报名。

5. 报名成功即进入开发与评审流程，无需等待名额释放；**报名先后顺序不影响评审结果与激励发放**。

#### 报名与评审规则：

| 规则项       | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| 报名顺序     | 仅用于报名登记、联络与进度跟踪，**不作为评审或发放依据**。   |
| 同一课题多人 | 允许并行开发，各自独立提交成果，分别进入验收与评审。         |
| 获奖判定     | 通过基础验收 + 综合评审且达到通过标准，并在该档**激励名额上限**内。 |
| 名额使用     | 按综合评审得分从高到低使用名额；名额用尽后，达标者不再发放激励，改发优秀贡献证书。 |
| 无效报名     | 材料缺失、关键信息无法核验或未实名认证的，不进入验收与评审。 |
| 重复提交     | 同一课题多次报名时，以最新一份完整、可核验的报名材料为准。   |

#### 课题状态说明：

活动页面将及时更新课题状态：

| 状态           | 颜色 | 含义                                                   |
| -------------- | :--: | ------------------------------------------------------ |
| **开放报名**   |  绿  | 可随时提交报名；同一课题允许多人报名。                 |
| **开发中**     |  蓝  | 已有开发者报名并进入开发，**仍可继续报名**。           |
| **待验收**     |  蓝  | 已提交 PR 与交付物，等待验收。                         |
| **评审中**     |  黄  | 基础验收或综合评审正在进行。                           |
| **已通过**     |  绿  | 成果达标并已发放激励。                                 |
| **达标未入额** |  橙  | 成果达标但该档名额已满，发放优秀贡献证书。             |
| **未通过**     |  红  | 两次验收未通过，本次不发放激励，可在后续批次重新报名。 |
| **已关闭**     |  灰  | 该课题所在档次名额已满或活动结束，不再接收报名。       |

### <a id="step3" name="step3" style="position:relative;top:-120px"></a><span style="color:rgb(222, 60, 54)">【第 3 步】报名资格核验</span>

1. 活动组对课题报名统一进行**基础资格核验**，核验内容包括：
   - AtomGit 账号一致性（报名、开发、验收、收款须为同一人）
   - 报名信息完整性与真实性
   - 基础项目经历与技术储备
   - 技术思路的可行性（是否体现智能体编排、工具调用与知识库能力）
   - 可投入时间与计划完成时间的合理性
2. 核验通过后即判定报名成功，招募小助手将在报名评论下回复"报名成功"并登记课题过程仓库；<span style="color:rgb(230, 162, 60)">核验通过仅代表可进入开发，不代表预留激励名额</span>。
3. 核验不通过者可在 **3 个自然日内**补充材料申请复验一次；仍不通过则本次报名无效，可在材料补齐后重新报名，不影响其他开发者。

### <a id="step4" name="step4" style="position:relative;top:-120px"></a><span style="color:rgb(222, 60, 54)">【第 4 步】课题开发</span>

#### 启动开发前，需满足前置条件：

1. 报名课题的开发者，需在资格核验通过、报名成功后的 **3 个自然日内**完成以下操作；规定时间内未完成且未获延期，视为该次报名未按期启动，活动组终止本次报名跟踪（**不影响其他开发者报名同一课题**）：
   - **Fork** [ModelEngine/AgentsHub](https://atomgit.com/ModelEngine/AgentsHub)，按[作品提交规范](#submission)在本仓库中建好课题目录骨架，并将 Fork 仓库链接反馈给招募小助手；
   - 同时开通课题过程仓库（或复用 Fork 仓库的课题目录）用于过程留痕，并为招募小助手开通管理员权限；
   - 提交课题开发技术方案与开发里程碑计划（含 `agent.json` 字段清单或初稿）。
2. **交付时间**：自报名成功之日起按下表里程碑推进，最终交付日期以报名时承诺的计划完成日期为准。

| 节点              | 时限                        | 交付内容                                                   |
| ----------------- | --------------------------- | ---------------------------------------------------------- |
| 技术方案 + 里程碑 | 报名成功后 3 个自然日内     | 架构图、智能体分工、工具与知识库清单、评测方案、里程碑计划 |
| 中期演示          | 报名成功后 30 个自然日内    | 可运行的核心链路 Demo（可录屏）                            |
| 正式交付          | 承诺的计划完成日期          | 完整交付物清单（见下）                                     |
| 验收评审          | 正式交付后 30 天内          | 基础验收 + 综合评审                                        |
| 整改复验          | 收到验收结果后 7 个自然日内 | 修复说明 + 修正版本                                        |

> 确有困难须在截止前 5 个自然日申请延期，经确认后生效，延长期限一般不超过 15 个自然日。

#### 进度更新要求：

1. 启动开发后，至少每 **7 个自然日**在课题过程仓库更新一次项目进展，规则如下：

| 节点             | 时限                              | 要求与处理                                                   |
| ---------------- | --------------------------------- | ------------------------------------------------------------ |
| **进度更新**     | 至少每 7 个自然日一次             | 在课题过程仓库更新**代码提交、Issue、测试记录、文档或阶段说明等操作**。仅口头说明不视为实际进展。 |
| **停更预警**     | 连续超过 7 个自然日无仓库更新     | 活动组发出预警后，开发者须在 3 个自然日内补充进展。          |

### <a id="step5" name="step5" style="position:relative;top:-120px"></a><span style="color:rgb(222, 60, 54)">【第 5 步】成果验收与评审</span>

#### 提交验收：

1. 在 Fork 仓库完成开发后，向 [ModelEngine/AgentsHub](https://atomgit.com/ModelEngine/AgentsHub) 提交 **Pull Request**（标题 `[new agent] <display_name>`，描述中注明课题序号与名称）；PR 经维护者审核合入 `main` 后，在 PR 评论或活动帖中提交验收申请并附合入链接。验收按批次组织，同一课题的多名开发者**分别独立评审**，互不影响。
2. **验收周期**：交付后 30 天内完成；提前交付的可提前申请验收。
3. 形式检查不通过（交付物缺失、仓库不规范、触碰红线）的，退回补齐后重新申请，不计入验收轮次。
4. **不设先到先得**：同一批次内的成果统一进入评审，结论只与成果质量相关，与提交先后、报名先后无关。

#### <a id="basic-acceptance" name="basic-acceptance" style="position:relative;top:-120px"></a>基础验收：

1. **基础验收重点**：
   - 满足开源要求（开源许可证、仓库规范、可复现部署）
   - 满足课题基础验收标准（详见《需求包详情与交付要求》，含通用验收标准与课题专属量化指标）
   - 测试用例完备性与有效性
   - 性能与稳定性（响应时延、批量处理耗时、重复执行一致性）
   - 文档及开发者体验
2. **实测演示**：评审现场随机抽取 3 条以上用例，开发者在干净环境部署并实机演示。
3. **指标复算**：评审按课题专属指标抽取样本复算，必要时提供复算环境与原始数据。
4. 首次基础验收不通过，开发者须在收到结果的 **7 个自然日内**完成修复并再次提交；二次基础验收仍不通过，则判定为"基础验收不通过"，本次不发放激励，可在名额未满时重新报名（不影响其他开发者）。

#### 综合评审：

1. 基础验收通过后进入**综合评审**，由活动组评审专家组织评审会，对交付成果按维度打分。

|      维度      | 权重 | 评审要点                                                   |
| :------------: | :--: | ---------------------------------------------------------- |
|   功能完整性   | 40%  | 课题建议功能与业务闭环是否全部实现，有无未实现环节         |
|  验收指标达成  | 30%  | 课题专属量化指标是否达成（准确率、召回率、时延、覆盖率等） |
|    工程质量    | 15%  | 架构合理性、代码规范、CI 通过、可维护性、异常处理          |
| 文档与可复现性 | 10%  | 他人能否依文档独立部署复现演示                             |
|   合规与安全   |  5%  | 数据合规、免责提示、出处溯源、许可证合规                   |

2. **通过标准**：
   - 加权得分 ≥ 80 分；
   - **验收指标维度必须 ≥ 70%**，单项指标未达标不允许用其他维度补分；
   - 合规与安全维度不得为 0 分，触碰红线直接判定不通过。
3. **同题择优规则**（同一课题多人达标时适用）：
   - 所有达标成果按综合评审得分从高到低排序，**在所在档次的激励名额上限内**确定获奖名单；
   - 得分相同时，依次比较「验收指标达成」得分、交付完整度、PR 首次提交时间之外的质量因素——**不以报名或提交先后作为排序依据**；
   - 名额用尽后，其余达标成果状态记为"达标未入额"，发放优秀贡献证书并在社区渠道展示；
   - 该课题的激励只发放 1 份，若多名开发者协作提交，激励发给 PR 作者，团队内部分配由开发者自行约定。
4. **有条件通过**：得分 ≥ 70 分且核心指标偏差 ≤ 10%，可判"有条件通过"，须在 10 个工作日内完成整改复验；复验仅复核问题清单条目，通过后进入名额排序。

## ⏰ 报名变更与激励名额规则

> 赛制原则：报名不占名额、不限人数；**激励名额只在实际发放时消耗**，不因报名先后或占位被提前占用。

### 报名变更规则

#### **场景 1：进展不满足要求**

1. 报名成功的 3 个自然日内，未向课题过程仓库提交技术方案与里程碑计划，且未获延期 → 活动组终止本次报名跟踪，**不影响其他开发者报名同一课题**。
2. 开发过程中连续超过 7 个自然日无仓库更新记录，经活动组预警后 3 个自然日内仍未更新 → 视为放弃本次开发，关闭进度跟踪；若在活动截止前补齐成果并申请验收，仍可参加当期评审。

> 进展更新要求详见[课题开发](#step4)。

#### **场景 2：开发者主动退出**

1. 报名及开发过程中，开发者可主动退出；退出后须及时通知活动组，并配合阶段资料交接。已提交并通过验收的成果不受影响。

#### **场景 3：多报名与同题并行**

1. 同一开发者同期最多报名 2 个课题，可并行开发；
2. 同一课题允许多人并行报名与开发，成果分别独立评审、互不影响；
3. 同一开发者就同一课题的多次提交，以最后一次通过验收的版本为准，激励只发 1 次。

#### **场景 4：违反行为规则**

1. 对代码抄袭、材料造假、数据红线违规、恶意刷报名或其他违规行为，由活动组评估认定后取消本次激励资格，已发放的激励全额追回。

| 情形                                 | 处理措施                                 |
| ------------------------------------ | ---------------------------------------- |
| 代码抄袭、套用他人成果未声明         | 判定不通过，取消后续参与资格             |
| 交付材料造假（数据、指标、评测结果） | 判定不通过，已发放激励全额追回           |
| 使用真实敏感数据违反红线             | 判定不通过，已发放激励全额追回           |
| 无实质进展、拒不更新或长期失联       | 关闭报名跟踪，不占用名额                 |
| 同一成果重复申报多个课题             | 仅认可一项，其余作废                     |
| 恶意刷报名、虚假材料占用评审资源     | 取消本次资格，情节严重者取消后续参与资格 |
| 冒用他人身份或代领激励金             | 取消资格，追回款项，保留追究权利         |

> ⚠️ 因抄袭、材料造假或其他违规行为被取消资格的开发者，不可申请报名其他课题。

### 激励名额使用规则

1. **名额只在发放时消耗**：报名、开发、提交 PR 均不占用名额；核验通过不等于预留名额。
2. **按档次统筹**：13 / 15 / 4 个名额分别为初级、中级、高级三个档次的总额，可在**同档不同课题之间统筹使用**；同一课题仍只发放 1 份激励。
3. **择优入额**：同档报名人数可超过名额数，达标成果按综合评审得分排序取前 N 名，具体规则见[第 5 步 · 同题择优规则](#step5)。
4. **未用满可延续**：某档名额未用满时，可在活动延期或下一批次继续使用；名额上限不因报名人数增加而扩大。
5. **违规追回回补**：因违规追回的激励金额与名额可回补至同档继续使用。
6. **公示要求**：名额发放情况在活动帖公示（课题、PR 链接、金额），不公示个人隐私信息；课题名额已满后状态更新为"已关闭"，其达标未入额者发放优秀贡献证书。
