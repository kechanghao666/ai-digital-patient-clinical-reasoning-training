# 权限矩阵（工程现状，2026-11-27）

本文按当前提交的代码逐条整理各主体对各类资源的实际权限，用于 M4 的"完整权限矩阵"交付项。
每格标注代码位置；"404/403/503"为实际返回。这不是安全认证结论，也不代表医学或官方验收；
未实现的管理员/教研主任角色、防篡改与主机文件权限仍为缺口（见文末）。

主体：

| 主体 | 说明 |
| --- | --- |
| 匿名 | 未登录、无有效 Bearer、无自填身份 |
| 学生 | 已认证 `student` 角色（独立账号模式）或本地演示 `student-`/`demo-` 自填身份（仅 `APP_ENV=development`） |
| 教师 | 已认证 `teacher` 角色；演示模式 `teacher-` 自填身份仅用于展示，不是名册账号 id |
| 运维 | 本机 CLI，`actor_id=local-ops`，依赖主机账号与文件权限，无网络入口 |

## 审计与保留现状

- `accounts.db` 内四张审计/配置表随离线备份恢复：账号管理审计、审核资质审计、去标识化导出审计、敏感访问审计（本轮新增，含留存预览、审计读取、预算变更）。
- 审计为追加式记录，非防篡改系统；读取仅限本机 CLI，每次读取本身留痕；数据库文件的主机访问权限由部署方限制。
- 覆盖范围：账号变更、资质变更、导出生成、留存预览、审计读取、预算变更。**不含**登录行为、学生自助改密、病例内容读取等"全站敏感访问"；历史事件不追溯补写。
- 无管理员/教研主任角色：`roles` 仅 `student|teacher`；跨教师移交、运维代操作教师资源没有产品流程，只能由部署方在数据库层面处理（不在本矩阵授权）。

## 主要缺口（承接覆盖表 M4/M10）

1. 外部真实资质核验与凭证：系统只记录运维确认，无执业认证。
2. 审计防篡改（WORM/签名）未实现；主机 ACL 验证未做。
3. 登录行为与学生自助改密审计未覆盖。
4. 留存政策只有预览，删除执行未实现（本轮明确不做）。
